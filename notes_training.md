# Сбор реальных данных и fine-tuning RealDepth

## Коротко: что нужно сделать

1. Не использовать `assets/realsense_*_depth.mp4` как правильные depth-метки.
   В этих MP4 записана цветная 8-битная визуализация глубины, а не исходные
   расстояния RealSense.
2. Подключить RealSense D435i и записать несколько **отдельных сессий** через
   `scripts/collect_dataset.py`.
3. Скрипт сам сохранит каждый момент как синхронную пару:

   ```text
   rgb/000000.png    # обычное RGB-изображение
   depth/000000.png  # исходная 16-битная глубина в миллиметрах
   ```

4. Разделить целые сессии на `train`, `val` и `test`.
5. Загрузить уже обученный синтетический checkpoint и выполнить fine-tuning на
   реальных данных.
6. Проверить готовую модель только на `test`-сессиях, которые не использовались
   при обучении.

## 1. Как правильно снимать данные

Лучше записывать не отдельные фотографии вручную и не два MP4, а поток
RealSense через готовый скрипт проекта. Фактически это всё равно видеозапись,
но каждый кадр сразу сохраняется без потери информации как пара PNG.

Из корня проекта:

```bash
source venv/bin/activate
python scripts/collect_dataset.py --duration 60 --fps 30
```

Каждый запуск создаёт отдельную папку, например:

```text
collected_dataset/20260821_190000/
├── rgb/
├── depth/
└── intrinsics.txt
```

Для начала желательно записать 20–30 сессий по 30–60 секунд. Для первого
технического эксперимента достаточно 5–10 разнообразных сессий, но этого мало
для убедительной оценки качества.

Во время записи:

- использовать одно разрешение `640x480` и один FPS для всех сессий;
- двигать робот и предметы плавно, чтобы не было размытия;
- показывать разные положения робота и захвата;
- менять количество, форму, размер и положение предметов;
- записать пустой стол и сложные случаи с перекрытиями;
- немного менять освещение и фон;
- не закрывать объективы RGB и depth;
- следить, чтобы цветной кадр и depth-карта показывали одну сцену.

Если в реальной работе камера будет закреплена, при сборе данных её тоже лучше
держать в рабочем положении. Основное разнообразие тогда создаётся движением
робота, предметами и освещением. Не следует обучать модель только на почти
одинаковых кадрах одного стола.

После каждой записи нужно открыть несколько файлов из `rgb/` и `depth/` и
проверить их. Depth PNG может выглядеть почти чёрным в обычном просмотрщике —
это нормально для 16-битного изображения. Нельзя преобразовывать его в
цветную heatmap или 8-битный PNG перед обучением.

## 2. Как разделить датасет

Разделять нужно **целые сессии**, например:

```text
16 сессий -> train
 2 сессии -> val
 2 сессии -> test
```

- `train` используется для изменения весов модели;
- `val` используется во время обучения для выбора лучшего checkpoint;
- `test` используется один раз для окончательной проверки.

Кадры одной записи нельзя случайно распределять между этими тремя частями:
соседние кадры почти одинаковые, поэтому возникнет утечка данных и метрики
получатся искусственно хорошими.

> **Важно:** текущий `scripts/split_dataset.py` перемешивает пересекающиеся
> последовательности кадров, а не разделяет данные строго по сессиям. Его можно
> использовать для быстрого пробного запуска, но перед настоящим экспериментом
> его необходимо изменить так, чтобы каждая сессия целиком попадала только в
> один split.

Команда для пробного разбиения:

```bash
python scripts/split_dataset.py \
  --input collected_dataset \
  --output dataset \
  --config configs/realsense.yaml
```

Она создаст структуру, которую ожидает обучение:

```text
dataset/
├── train/{rgb,depth}
├── val/{rgb,depth}
└── test/{rgb,depth}
```

Если папка `dataset` уже существует, скрипт попросит подтверждение перед её
заменой.

## 3. Настройка fine-tuning

В проекте уже есть синтетический checkpoint:

```text
experiments/kuka/checkpoints/best.pth
```

Перед обучением открыть `configs/realsense.yaml` и настроить как минимум:

```yaml
exp_name: realsense_finetune
data_dir: ./dataset

max_depth: 3.0       # максимальная нужная глубина в метрах; изменить при необходимости
depth_scale: 0.001   # depth PNG хранит миллиметры
image_size: [480, 640]
sequence_length: 3

pretrained_checkpoint: experiments/kuka/checkpoints/best.pth

epochs: 40
batch_size: 2
lr: 0.0001
encoder_lr: 0.00001
freeze_encoder_epochs: 10
```

`max_depth` должен покрывать рабочий диапазон камеры. Для небольшого стола
обычно можно начать с `3.0`, а если в данных есть правильная глубина больше
трёх метров — увеличить значение.

Небольшой `encoder_lr` нужен, чтобы не разрушить уже выученные признаки.
Сначала encoder будет заморожен, затем скрипт автоматически разморозит его и
продолжит fine-tuning всей модели.

> Сборщик сейчас сохраняет `intrinsics.txt`, а temporal dataset ищет
> `intrinsics.json`. Поэтому при отсутствии JSON код использует стандартные
> параметры камеры. Для серьёзного camera-aware эксперимента нужно согласовать
> эти форматы и передавать реальные intrinsics в датасет.

## 4. Запуск обучения

Установить окружение, если это ещё не сделано:

```bash
python3.10 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python setup.py develop
```

Запустить fine-tuning:

```bash
source venv/bin/activate
python scripts/train.py --config configs/realsense.yaml
```

Если доступна CUDA, скрипт автоматически использует GPU. Результаты появятся в:

```text
experiments/realsense_finetune/
├── checkpoints/best.pth
├── visualizations/
└── logs/
```

Основной результат — `checkpoints/best.pth`. Он сохраняется по лучшему значению
ошибки на validation-части.

TensorBoard можно открыть командой:

```bash
tensorboard --logdir experiments/realsense_finetune/logs
```

Во время обучения нужно смотреть не только на `train loss`, но и на `val loss`,
`AbsRel`, `MAE`, `RMSE`, `delta1`, а также на картинки из `visualizations/`.
Если train loss продолжает падать, а val loss растёт, модель переобучается.

## 5. Финальная проверка

После обучения проверить лучший checkpoint на отдельном test split:

```bash
python scripts/validate.py \
  --checkpoint experiments/realsense_finetune/checkpoints/best.pth \
  --config configs/realsense.yaml \
  --split test
```

Затем проверить модель на одном изображении:

```bash
python scripts/infer_image.py \
  --checkpoint experiments/realsense_finetune/checkpoints/best.pth \
  --image path/to/image.png
```

Или запустить проверку с камерой:

```bash
python scripts/infer_camera.py \
  --checkpoint experiments/realsense_finetune/checkpoints/best.pth
```

## Чего не делать

- Не обучать модель на цветных `*_depth.mp4`.
- Не переводить исходный depth в JPEG или обычный 8-битный PNG.
- Не делить соседние кадры одной записи между train и test.
- Не использовать test-сессии для настройки модели.
- Не смешивать данные с разным масштабом глубины без корректного `depth_scale`.
- Не оценивать качество только по красивой цветной heatmap — нужны метрики на
  невидимых модели test-данных.

## Итоговый чек-лист

- [ ] Записано не меньше 5–10 пробных или 20–30 полноценных сессий.
- [ ] Для каждого RGB PNG есть одноимённый 16-битный depth PNG.
- [ ] Все записи имеют одинаковое разрешение и масштаб глубины.
- [ ] Сессии целиком разделены на train/val/test.
- [ ] В конфиге указан синтетический `pretrained_checkpoint`.
- [ ] Fine-tuning завершён, сохранён `best.pth`.
- [ ] Метрики посчитаны на отдельном test split.
- [ ] Модель проверена на новых сценах в реальном времени.
